# 可配置订阅套餐设计

## 背景

当前充值包已由 `/admin/top-up-products` 管理并从 D1 读取；订阅套餐仍然写在 `src/config/pricing.ts` 和 `src/blocks/pricing.tsx`。因此后台改充值包不会改变首页的 Lite、Pro、Ultra 月付/年付方案。

## 目标

让管理员可以在后台配置一次性充值包和周期订阅套餐。订阅套餐的后台数据同时驱动首页展示和结账；服务端以数据库值为准，客户端提交的金额、积分和周期均不可信。

## 方案

新增独立的订阅套餐表和订阅套餐管理页/API，与现有充值包表、管理页和 API 并列。订阅表保存稳定产品 ID、名称、描述、价格、可选划线原价、币种、计费周期及次数、每周期积分、积分有效期、首页卖点、推荐标记、启用状态和排序。中英文展示字段分别保存，货币继续使用 USD。沿用现有 RBAC `admin.*`、Origin 检查和公开 API 安全字段投影。

公共套餐 API 只返回启用产品的展示字段。首页按 locale 获取套餐列表、分月付/年付展示，并使用返回的 `productId` 发起结账。结账服务端优先查找有效订阅套餐，再查找充值包；订阅类型、金额、周期、积分和有效期全部从数据库解析。Creem 继续复用已有 `creem_product_ids_mapping` 设置映射内部产品 ID 到支付商产品 ID；Stripe 使用动态周期价格，PayPal 使用其现有订阅创建流程。

后台不能删除产品，只能停用或调整。修改套餐只影响之后创建的订单；订单及现有订阅保留结账时写入的名称、金额、积分和周期数据。旧的六个 Lite/Pro/Ultra 月付/年付方案作为初始配置迁移到数据库。

## 页面与字段

- 账单导航提供“充值包”和“订阅套餐”独立入口。
- 订阅套餐字段：产品 ID（创建后不可改）、计划名称、中英文名称与描述、中英文卖点（每行一项）、美元价格和可选划线原价、月/年周期与周期次数、每周期积分、积分有效期、推荐标记、启用状态、排序。
- 年付方案展示实际年费，同时由年费和对应月付价格计算月均价及节省比例；结账始终使用实际年费。
- 用户未登录仍可浏览套餐；购买仍要求登录。购买充值包不要求先订阅。

## 安全与数据

- 只有已登录且具有 `admin.*` 权限的管理员可读写后台 API；写请求必须通过同源 Origin 检查。
- 公共 API 不返回管理字段或支付密钥。服务端结账按稳定产品 ID 查库，忽略客户端传入的价格、类型、积分及周期。
- 生产迁移采用 additive SQL：创建订阅套餐表并插入默认六档，不重建现有表。上线前由用户审核迁移，再应用到 D1。

## 验收标准

1. 管理员可以新增、编辑、排序、启用/停用订阅套餐；普通用户不可访问后台 API。
2. 首页能按语言展示后台启用的月付/年付套餐、描述、卖点和推荐标记；停用项不显示。
3. 结账只采用服务端已启用套餐的权威数据，未知或停用 ID 不能购买。
4. 六个现有方案通过迁移进入后台，最终首页价格和积分不变。
5. 充值包配置和购买行为保持可用，充值包仍允许任何已登录用户购买。
6. `pnpm build` 通过，安全扫描无阻断项。
